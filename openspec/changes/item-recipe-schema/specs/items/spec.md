# Spec Delta: Items (Recipe Schema + Icons)

## MODIFIED Requirements

### Requirement: Item data model SHALL represent a catalog entry, not per-user stock

An `Item` SHALL carry `id`, `nombre` (required), `categoria` (optional
free text), `esMateriaPrima` (boolean, default `false`), `fullId`
(optional string, the Minecraft namespaced id used for icon lookup),
`recetaMatriz` (optional list of exactly 9 entries, each an item id or
`null`), and `ingredientesParaCalculo` (a server-computed list of
`{itemId, cantidad}`, derived from `recetaMatriz`). It SHALL NOT carry a
quantity/stock field or an unused icon-string field.

#### Scenario: Creating an item without a categoria

- **WHEN** a client creates an item with only `nombre` set
- **THEN** the created item SHALL have `categoria = null` and
  `esMateriaPrima = false`

#### Scenario: Creating an item without a nombre is rejected

- **WHEN** a client sends `POST /api/items` with a blank or missing `nombre`
- **THEN** the response status SHALL be 400
- **AND** no document SHALL be created

#### Scenario: Creating an item with a recipe computes ingredientesParaCalculo

- **GIVEN** a client creates an item with `recetaMatriz` containing
  `"lana"` three times and `"tablones_de_roble"` three times (9 slots
  total, the rest `null`)
- **WHEN** the item is persisted
- **THEN** the stored `ingredientesParaCalculo` SHALL equal
  `[{itemId: "lana", cantidad: 3}, {itemId: "tablones_de_roble", cantidad: 3}]`
- **AND** any `ingredientesParaCalculo` value sent by the client SHALL be
  ignored in favor of this computed value

### Requirement: Item ids SHALL be derived from nombre, not database-autogenerated

On creation, an `Item`'s Firestore document id SHALL be derived from its
`nombre` via slug conversion (lowercase, diacritics stripped, spaces
replaced with `_`). The id SHALL NOT change when the item is later updated,
even if `nombre` changes. Creating an item whose derived id already exists
SHALL be rejected rather than overwriting the existing document.

#### Scenario: New item gets a slug id

- **WHEN** a client creates an item with `nombre = "Arcilla"`
- **THEN** the created item's `id` SHALL be `"arcilla"`

#### Scenario: Renaming an item does not change its id

- **GIVEN** an existing item with `id = "arcilla"` and `nombre = "Arcilla"`
- **WHEN** the client sends `PUT /api/items/arcilla` with `nombre = "Bola de Arcilla"`
- **THEN** the item's `id` SHALL remain `"arcilla"`

#### Scenario: Creating an item whose slug id already exists is rejected

- **GIVEN** an existing item with `id = "arcilla"`
- **WHEN** a client sends `POST /api/items` with `nombre = "Arcilla"`
- **THEN** the response status SHALL be 409
- **AND** the existing `arcilla` document SHALL NOT be modified

### Requirement: Updating or deleting a non-existent item SHALL report not-found

`PUT /api/items/{id}` and `DELETE /api/items/{id}` MUST NOT silently create
or no-op on an id that does not exist in the `items` collection; they SHALL
respond with 404.

#### Scenario: Updating an unknown id

- **GIVEN** no item exists with id `"missing-1"`
- **WHEN** the client sends `PUT /api/items/missing-1` with a valid body
- **THEN** the response status SHALL be 404
- **AND** no document SHALL be created at that id

#### Scenario: Deleting an unknown id

- **GIVEN** no item exists with id `"missing-1"`
- **WHEN** the client sends `DELETE /api/items/missing-1`
- **THEN** the response status SHALL be 404

### Requirement: Search SHALL match name or category, with an optional materials filter

`GET /api/items` SHALL accept an optional `q` parameter matched
case-insensitively as a substring of `nombre` OR `categoria`, and an optional
`esMateriaPrima` boolean parameter that, when present, restricts results to
items whose `esMateriaPrima` equals the given value.

#### Scenario: Searching by category text

- **GIVEN** items exist with `categoria` values `"Mineral"` and `"Herramienta"`
- **WHEN** the client sends `GET /api/items?q=miner`
- **THEN** only items whose `nombre` or `categoria` contains `"miner"`
  (case-insensitive) SHALL be returned

#### Scenario: Filtering to raw materials only

- **GIVEN** items exist with `esMateriaPrima = true` and `esMateriaPrima = false`
- **WHEN** the client sends `GET /api/items?esMateriaPrima=true`
- **THEN** only items with `esMateriaPrima = true` SHALL be returned

### Requirement: The web item forms SHALL surface validation failures

The `/items` create form and the `/items/{id}/edit` update form MUST
re-render with an actionable error message when submission fails validation,
instead of silently discarding the failure.

#### Scenario: Submitting a blank name on the web create form

- **WHEN** an authenticated user submits `POST /items` with a blank `nombre`
- **THEN** the response SHALL re-render the items page with an `error`
  message
- **AND** no item SHALL be created

## ADDED Requirements

### Requirement: recetaMatriz SHALL be validated for shape before persisting

`recetaMatriz`, if provided, MUST have exactly 9 entries. An item with
`esMateriaPrima = true` MUST NOT have a non-empty `recetaMatriz`. Either
violation MUST be rejected (400 for REST, a re-rendered form with a
Spanish error for web) without persisting.

#### Scenario: Recipe with the wrong number of slots is rejected

- **WHEN** a client sends `POST /api/items` with `recetaMatriz` containing
  5 entries
- **THEN** the response status SHALL be 400
- **AND** no document SHALL be created

#### Scenario: A raw material cannot carry a recipe

- **WHEN** a client sends `POST /api/items` with `esMateriaPrima = true`
  and a non-empty `recetaMatriz`
- **THEN** the response status SHALL be 400
- **AND** no document SHALL be created

### Requirement: Item creation/edit SHALL offer icon suggestions derived from nombre

`GET /api/items/sugerencias-icono?nombre=...` SHALL translate the given
Spanish `nombre` into English via a curated dictionary, query
`blocksitems.com`'s item search, and return up to 5 candidates
(`fullId`, `displayName`, `iconUrl`), with `namespace=minecraft` results
ranked above other namespaces. If translation yields no results, the
endpoint SHALL retry with the raw `nombre` before returning an empty list.
This endpoint SHALL require an authenticated session, consistent with the
rest of `/api/items`.

#### Scenario: Suggesting an icon for a Spanish item name

- **GIVEN** an authenticated session
- **WHEN** the client sends `GET /api/items/sugerencias-icono?nombre=Tablones%20de%20Roble`
- **THEN** the response SHALL include a candidate with
  `fullId = "minecraft:oak_planks"`

#### Scenario: No matches found

- **GIVEN** an authenticated session
- **AND** a `nombre` with no dictionary entry and no search results
- **WHEN** the client requests suggestions for that `nombre`
- **THEN** the response SHALL be an empty list, not an error

#### Scenario: Unauthenticated request is rejected

- **GIVEN** a request with no session
- **WHEN** the client sends `GET /api/items/sugerencias-icono?nombre=Roca`
- **THEN** the response status SHALL be 401

### Requirement: Item listings SHALL render an icon when fullId is present

Any page listing items SHALL render an `<img>` sourced from
`https://blocksitems.com/api/v1/items/{fullId}/icon`, with a fallback
image shown if the request fails, for any item whose `fullId` is set.

#### Scenario: An item with fullId shows its Minecraft icon

- **GIVEN** an item with `fullId = "minecraft:clay_ball"`
- **WHEN** the items page renders that item's row
- **THEN** the row SHALL include an `<img>` element sourced from
  `https://blocksitems.com/api/v1/items/minecraft:clay_ball/icon`
